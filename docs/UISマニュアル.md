# UISマニュアル

## 基本記法

- カスタム要素の場合
```
_{要素名}
    type={要素タイプ}
    {プロパティA}={値A}
    {プロパティB}={値B}
    {プロパティC}={値C}
```

- 組み込み要素の場合
```
{要素名}
    {プロパティA}={値A}
    {プロパティB}={値B}
    {プロパティC}={値C}
```

`#`から始めることでその行はコメントになります

### 一括定義（バッチ定義）

`_{要素名}-[0-10]` のように記述することで、`_{要素名}-0` から `_{要素名}-10` まで同じプロパティを持つ要素をまとめて定義できます。

```
_Note-[0-10]
    type=0
    size=100,100
    anchor=4
```

上記の例では `_Note-0` ～ `_Note-10` の11要素すべてに同一プロパティが設定されます。

一括定義の後、特定のインデックスだけ個別に上書き定義することも可能です：

```
_Note-[0-10]
    size=100,100

_Note-5
    size=200,200
```

この場合、`_Note-5` のみサイズが 200,200 になります。


## 組み込み要素について
UISではいくつかの組み込み要素が存在します。（簡単に言うとノートやヒットエフェクト等、プレイに必須のものです。）
組み込みスプライトには以下の種類があります。
これらは通常のスプライトとは違い、"_"で始める必要はありません。

|組み込み要素名称|意味|備考|
|-|-|-|
|note|ノート|Keyの数だけ定義できます|
|key|キー|Keyモードにおける仮想ボタンになります。|
|hit|ヒットエフェクト|-|
|press|Keyモードにおける、Key押下時のエフェクト|フレームである必要があります|
|judge|判定時に発生するエフェクト|Best, Cool, Good, Miss の4種類の判定があります|
|hit-fast|早いCool判定時に発生するエフェクト|-|
|hit-slow|遅いCool判定時に発生するエフェクト|-|
|score-combo|コンボテキスト|-|
|score-score|スコアテキスト|-|
|score-acc|acc(精度)テキスト|-|
|score-hp|HPバー|-|
|bga|BGAが再生される位置|BMSフォーマットの譜面のみ対象です。|
|touch|タッチエリア|モバイル端末でスキンを使用する場合は必須です。|
|progress|譜面の進行状況|-|
|bar|小節線|-|
|pause|ポーズボタン|-|

上記の組み込みスプライトの詳細については後ほど解説します。

## コマンド
組み込みスプライトに加えて、UISでは以下のコマンドが使用できます。
これらは通常UISドキュメントの先頭に記載します。（先頭でなくても問題はありません。）

|コマンド名称|意味|
|-|-|
|@apply 3d|スキンを3D表示にする。
|@best {サウンドファイル名}.ogg|Best時のヒットサウンドを指定する|
|@cool {サウンドファイル名}.ogg|Cool時のヒットサウンドを指定する|
|@good {サウンドファイル名}.ogg|Good時のヒットサウンドを指定する|
|@miss {サウンドファイル名}.ogg|Miss時のヒットサウンドを指定する|
|@version {バージョン名: x.x.x}|スキンをサポートする最低バージョンを設定する。設定したバージョンより下のバージョンでは使えなくなる。|
|@apply soundend|ホールドノートの終点でタップ音が鳴るようにする。|
|@angle {斜度}|3Dスキンの斜度を設定する。（50までが推奨）|
|@include {UISファイル名}.uis|ほかのUISファイルを参照する。|
|@texpack {スプライトシート名}|スプライトシートを使用できるようにする。|
|@unit 1080|画面の高さの相対サイズを設定する。|
|@define {変数名} {値}|変数を定義する。数値型のみ|
|@if {条件}|指定した条件を満たす場合、@endifまで構文を実行する。|
|@endif|@ifで指定された条件に満たす場合、@ifとの間にある構文を実行する。|


## 各要素に設定出来るプロパティについて

設定できるプロパティは以下の通りです。

| プロパティ | 意味 | 備考 |
|-----------|------|------|
| tex | 画像要素に適用する画像ファイル名 | 対応する拡張子は png, jpg, bmp の3種類。画像要素と伸縮画像のみ設定可 |
| size | 要素のサイズ（幅、高さ） | 詳細は後述。 |
| pos | 要素の位置（x座標、y座標） | 詳細は後述。 |
| anchor | 要素のアンカーポイント | 0〜8の順に、左上、中上、右上、中左、正中、中右、左下、下中、右下。 |
| frame | アニメーション要素に適用する画像ファイル名 | 対応する拡張子は png のみ。詳細は後述。 |
| interval | アニメーション要素におけるインターバル | アニメーション要素のみ設定可。 |
| color | 要素に適用する色 | カラーコードで記載する。 |
| rotate | 要素の角度 | 0〜360 |
| flip | 要素の表示を反転する | 0⇒水平方向に反転、1⇒垂直方向に反転。未設定の場合は反転しない |
| opacity | 要素の透明度 | 0〜100で指定。0は不可視、100は不透明状態。 |
| zindex | 要素のZインデックス | 数字が大きいほど他の要素より前面に表示する。 |
| fsize | テキスト要素のフォントサイズ | テキスト要素のみ設定可 |
| part | 伸縮画像（type=4）の伸縮範囲 | 画像のサイズを変更するときにどの範囲を伸縮させるか指定する。伸縮画像要素のみ設定可 |
| rect | 9スライス画像（type=5）の伸縮範囲 | 画像のサイズを変更するときにどの範囲を伸縮させるか指定する。伸縮画像要素のみ設定可 |
| blend | レイヤーの合成モード | 0⇒加算、1⇒スクリーン。 |
| text | テキスト要素に適用するテキスト | 要素に表示する文字列。テキスト要素のみ設定可 |
| motion | 適用するUISアニメーション | 対応するUISアニメーションを定義する必要があります |
| parent | 親要素名 | 指定した要素の子要素となり、`pos` プロパティなどが親要素から相対的に計算されるようになります。 |
| type | 要素の種類 | 設定対象の要素の種類によって意味が異なる。後述。 |

### type
#### type=0 （デフォルト値）
要素を画像要素として設定します。
実際に画像を表示するには `tex`プロパティを指定し、適用する画像ファイルを指定する必要があります。

#### type=1
要素をテキスト要素として設定します。
実際にテキストを表示するには`text`プロパティで表示するテキストを指定する必要があります。
また、特別なプレースホルダーを使用して譜面のメタデータを引用することができます。
- {title} : 曲名
- {artist} : 作曲者名
- {creator} : 譜面作者
- {version} : バージョン名（例：Hard Lv.18）
- {bpm} : BPM
- {player} : プレイヤー名

#### type=2
要素を長方形要素として設定します。
`color`プロパティで色を指定しないと見えません。

#### type=3
要素をアニメーション要素として設定します。
`frame`プロパティで画像ファイル、`interval`プロパティでアニメーションの速度を指定する必要があります。
記法：`frame=image/0-1` --この場合、image-0.png, imgage-1.pngのフレームとして指定されることになる

#### type=4（Stretch / 伸縮画像）
基本的に`type=0`の画像要素と同じですが、画像の伸縮方法が異なります。
`part`プロパティで指定した範囲のみ伸縮され、ほかの部分は元のサイズを保持します。
記法: `part={始点のx座標},{終点のx座標}`
デフォルト状態では水平方向の伸縮のみ有効ですが、`type2=1`というプロパティを追加で記載することで垂直方向の伸縮が適用できます。

#### type=5（Ninepatch / 9スライス画像）
基本的に`type=0`の画像要素と同じですが、画像の伸縮方法が異なります。
`rect`プロパティで指定した範囲（長方形）のみ伸縮され、ほかの部分は元のサイズを保持します。
記法：`rect={左上隅のx座標},{左上隅のy座標},{幅},{高さ}`

### プロパティのデフォルト値

プロパティが省略された場合は以下のデフォルト値が適用されます。

| プロパティ | デフォルト値 | 備考 |
|-----------|------------|------|
| anchor    | 4          | 正中（中央） |
| pos       | 0%,0%      | 左下隅（X=0, Y=0） |
| size      | 0,0        | 両方0の場合は元画像サイズを使用。片方のみ0の場合はアスペクト比を維持して自動計算 |
| opacity   | 100        | 不透明 |
| rotate    | 0          | 回転なし |
| zindex    | 0          | |

**size の特殊動作について：**
- `size=0,0` → 元画像の幅・高さをそのまま使用
- `size=0,200` → 高さ=200 に合わせてアスペクト比を維持した幅に自動設定
- `size=100,0` → 幅=100 に合わせてアスペクト比を維持した高さに自動設定

### zindex と 3D 表示

`@apply 3d` が有効な場合、**zindex が 1〜99 の要素には `@angle` で設定した傾斜が適用されます。**

| zindex 範囲 | 挙動 |
|------------|------|
| 0          | 2D 表示（背景等） |
| 1 〜 99    | 3D 傾斜が適用（ノート、ヒットエフェクト等） |
| 100 以上   | 2D 表示（UI オーバーレイ等） |

`@angle` の値はスクリーンに対する傾斜角度（度）です：
- `@angle 0` → スクリーンと平行（完全に平ら）
- `@angle 45` → 45° 傾斜（一般的な音ゲーの視点）
- `@angle 90` → スクリーンと直角（側面から見た状態）

通常は 45 前後が推奨されます（50 まで推奨）。

### size、pos
3種類の表現方法があります。

#### 相対サイズでの指定
単位無しで記載します。（例：size=100,100）
この記載方法では`1=現在のゲームウィンドウの高さ÷720`に相当します。
例えば、`1280×720`のウィンドウでは、1は1ピクセルに相当します。`1920×1080`のウィンドウでは、1は1.5ピクセルに相当します。
`@unit`コマンドの影響を受けます

#### 絶対サイズでの指定
単位を付けて記載します。（例：size=100px,100px）

#### パーセンテージでの指定
パーセンテージで表現します。（例：pos=50%,50%）
また、3種類の記載方法を組み合わせたり、演算子を使うこともできます。
例１：size=50%,100
例２：pos=100%-5px,200

### anchor
要素の基準点になる位置を設定します。
`pos`プロパティや`rotate`プロパティの基準になるので重要なプロパティです。

## 組み込みスプライトについて（詳細）
### note
- tex=通常のノート用の画像
- tex2=ロングノート用の画像
- tex3=ロングノートの終点用の画像
- tex4=同時押しノート用の画像
- tex5=ロングノートの始点用の画像（指定しない場合はtexで指定した画像になる）
- pos=ノートが初めて表示される位置
- pos2=ノートをたたく（タップする）位置。判定が発生する位置。
- size=ノートが初めて表示されるときのサイズ。posにおけるサイズ。
- size2=ノートをたたく（タップする）時のサイズ。pos2におけるサイズ。
- ノーツをタップした際に画像を不可視に場合は`toggle=1`、ロングノートを押している間に始点(tex5)の画像をタップしたタイミングの位置で固定させたい場合は`toggle=2`、
どっちも適用させたい場合は`toggle=1+2`というプロパティを追加で記載する。

### key
- texプロパティ=通常時の画像
- tex2プロパティ=keyを押したときの見た目用の画像

### hit
hitはアニメーション要素なので`frame`プロパティを指定する必要があります。
- frame=通常のノートをタップしたときのエフェクト
- frame2=ロングノートを押している間のエフェクト
- frame3=ロングノートを離したときのエフェクト

### press
pressはアニメーション要素なので`frame`プロパティを指定する必要があります。
- frame=key押下時のアニメーションの画像ファイル
- frame2=keyを離したときのアニメーションの画像ファイル

### judge
`type`プロパティで表示方法を変更することができます。

#### type=1
Best/Cool/Good/Missの順にxxxx-0.png、xxxx-1.png、xxxx-2.png、xxxx-3.png という名前を付けた画像を用意する必要があります。
画像要素ですが、`frame`プロパティを使用して表現します。
記法：`frame=xxxx/0-3`

#### type=2
「判定＋この判定の総数」を表示することができます。
判定の部分のフレームはtype=1と同じ記法で指定します。
数字部分のフレームは「0~9」「％」「小数点」「+」「-」「×」の順にxxxx-0.ongからxxxx-14.pngという名前を付けた画像を用意したうえで`frame2`プロパティとして指定する必要があります。
記法：`frame2=xxxx/0-14`で指定する必要があります。

#### type3
判定を画像要素ではなくアニメーション要素で表示することができます。
- frame=Best時のアニメーション
- frame2=Cool時のアニメーション
- frame3=Good時のアニメーション
- frame4=Miss時のアニメーション

### hit-fast,hit-slow
hit-fast,hit-slowはアニメーション要素なので`frame`プロパティを指定する必要があります。

### score-combo,score-score,score-acc
・frame=数字の画像（judge要素のtype=2の説明で出てきた命名規則と同じです）
・interval=数字が増加するスピード(1から2に切り替わるスピード)
・pos2=数字間の距離（表示されている数字が2桁以上の場合に有効）
※pos2の値は1がデフォルト

### score-hp
`type`プロパティで表示方法を変更することができます。

#### type=0
`tex`プロパティでHPバーの画像を指定します。
HPが減ると画像が右側から左側に消えていきます。この方向はrotateプロパティで変更できます。

#### type=1
HPを画像の数で表現します。
「HPがある状態」「HPがない状態」の順にxxxx-0.png、xxxx-1.pngという名前を付けた画像を用意する必要があります。
画像要素ですが、`frame`プロパティを使用して表現します。
記法：`frame=xxxx/0-1`
また、表示する画像の数は`count`プロパティで指定します。`count`の数とフレーム数は一致している必要があります。

### progress
score-hpと同じように記載します。

### bar
・pos、pos2、size、size2プロパティをnoteと同じように記載します。

### touch
keyの数だけ定義する必要があります。
例えば4Kならrect1(array1)、rect2(array2)、rect3(array3)、rect4(array4)が必要です。
`type`プロパティで指定方法を変更することができます。

#### type=1
タッチエリアは長方形になります。
`rect=x,y,w,h`というように記載します。
- x＝左下のx座標
- y=左下のy座標
- w=幅
- h=高さ

#### type=2
タッチエリアは円形になります。
`rect=x,y,w`というように記載します。
- x＝左下のx座標
- y=左下のy座標
- w=半径

#### type=3
タッチエリアは三角形になります。
`array=x1,y1,x2,y2,x3,y3`というように記載します。
- x1＝頂点1のx座標
- y1=頂点1のy座標
- x2＝頂点2のx座標
- y2=頂点2のy座標
- x3＝頂点3のx座標
- y3=頂点3のy座標

#### type=10
上記のtype=1,2,3を組み合わせることができます。
type=1にしたいなら、`array=1,x,y,w,h`
type=2にしたいなら、`array=2,x,y,w`
type=3にしたいなら、`array=3,x1,y1,x2,y2,x3,y3`
というように記載します。
また、`type=10`の場合はタッチエリアを重ねることができますが、スコアを送信することができなくなります。
